# Сервис онлайн-аукциона коллекционных предметов (Лабораторная работа №3)

RESTful веб-приложение для проведения торгов редкими и коллекционными предметами. Реализовано на стеке Spring Boot 3, Spring Data JPA и PostgreSQL.

---

## 1. Назначение приложения
Сервис автоматизирует полный жизненный цикл аукционных торгов: от регистрации участников и добавления лотов с предметами коллекционирования до приёма конкурентных ставок, фиксации победителя и передачи права собственности.

---

## 2. Предметная модель (Основные сущности)

- **User (`users`)** — участник аукциона (продавец или покупатель).
- **CollectibleItem (`collectible_items`)** — предмет коллекционирования (название, описание, текущий владелец `owner`, состояние).
- **AuctionLot (`auction_lots`)** — аукционный лот, привязанный к предмету. Содержит стартовую цену, шаг ставки, временные рамки и статус (`CREATED`, `ACTIVE`, `CLOSED`, `CANCELLED`).
- **Bid (`bids`)** — ставка участника в рамках конкретного лота с фиксацией времени и суммы.
- **AuctionDeal (`auction_deals`)** — сделка по итогам торгов. Связывает лот, ставку-победитель и статус передачи права собственности (`PENDING`, `TRANSFERRED`, `CANCELLED`).

---

## 3. Реализованные бизнес-операции

Все бизнес-операции изолированы в сервисе `AuctionBusinessService` и выполняются транзакционно (`@Transactional`):

1. **Активация лота (`POST /api/business/lots/{id}/activate`)**  
   Проверяет корректность дат и текущий статус лота (`CREATED`). Переводит лот в статус `ACTIVE` для открытия приёма ставок.
2. **Размещение ставки (`POST /api/business/lots/{id}/bids`)**  
   Затрагивает сущности `AuctionLot`, `Bid` и `User`. Проверяет активность лота, валидирует, что ставка превышает текущую максимальную ставку (или стартовую цену) минимум на величину шага `bidStep`. Запрещает владельцу лота делать ставки на свой предмет.
3. **Закрытие торгов и формирование сделки (`POST /api/business/lots/{id}/close`)**  
   Затрагивает `AuctionLot`, `Bid` и `AuctionDeal`. Переводит лот в статус `CLOSED`. Если ставки были, автоматически формирует сделку `AuctionDeal` со статусом `PENDING`. Если ставок не было, сделка не создаётся.
4. **Исполнение сделки и передача права собственности (`POST /api/business/deals/{id}/complete`)**  
   Затрагивает `AuctionDeal`, `CollectibleItem` и `User`. Проверяет статус сделки (`PENDING`), меняет статус сделки на `TRANSFERRED` и переписывает поле `owner` предмета на пользователя, сделавшего победную ставку.
5. **Отмена лота (`POST /api/business/lots/{id}/cancel`)**  
   Затрагивает `AuctionLot` и `AuctionDeal`. Досрочно переводит лот в статус `CANCELLED`. Если по лоту уже была сформирована незавершённая сделка, аннулирует её со статусом `CANCELLED`.
